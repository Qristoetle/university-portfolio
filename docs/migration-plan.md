# 项目整理与迁移流程

1. 清点原始源码、正式交付包、报告、PPT 和视频，记录版本日期。
2. 使用独立副本整理，保留原交付材料；正式版本优先，缺失配置注明补充来源。
3. 统一仓库名称和 README，保留源码依赖的路径，确认依赖与运行命令。
4. 从公开版本中移除真实密钥、环境文件、SDK、依赖目录、缓存和重复历史材料。
5. 按数据来源选择公开样例或已生成结果；完整数据的获取条件写入 README。
6. 运行已有测试、构建及文件检查，再创建仓库并上传。
7. 检查 GitHub 首页、相对链接、图片及仓库可见性，更新作品集索引。

## 素材管理

截图及图表放在 `assets/` 或结果目录；最终报告和 PPT 放在 `docs/`。大视频、完整交付压缩包及数据集保留独立归档，后续按实际需要发布为附件。首批上传不使用 Git LFS。
